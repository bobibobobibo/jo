## User Scenarios & Testing *(mandatory)*

### User Story 1 - 設定賽前進站策略 (Priority: P1)

玩家在開始比賽前，可以在策略規劃畫面中決定預計的進站圈次與換胎選擇，完成設定後進入比賽，系統依照玩家的策略安排提示進站時機。

**Why this priority**：賽前策略設定是本功能的核心——讓玩家從被動操作晉升為具有主動決策感的賽車手。即使只有此故事可用，玩家就能體驗策略規劃到比賽執行的完整流程，具備獨立交付價值。

**Independent Test**：可透過開啟策略規劃畫面、選定進站圈次與輪胎種類、確認開始比賽，並在遊戲中驗證系統是否在預設圈次前顯示進站提示來完整驗證。

**Acceptance Scenarios**:

1. **Given** 玩家在比賽開始前的設定畫面，**When** 玩家開啟策略規劃頁籤，**Then** 畫面顯示當前賽道的總圈數、輪胎選項（軟胎、中性胎、硬胎）與可新增進站計畫的界面。
2. **Given** 玩家在策略規劃畫面，**When** 玩家選擇第 N 圈作為進站圈次並選定換胎種類後儲存，**Then** 策略摘要區域顯示已設定的進站計畫，包含圈次與輪胎類型。
3. **Given** 玩家已設定策略並開始比賽，**When** 遊戲計圈數到達設定的進站圈，**Then** 螢幕顯示「準備進站」提示，引導玩家前往維修站。

---

### User Story 2 - 即時查看目前策略執行狀況 (Priority: P2)

玩家在比賽過程中，可以隨時查看目前的輪胎狀態與剩餘策略規劃，以便即時判斷是否需要調整進站時機。

**Why this priority**：比賽中的策略資訊顯示讓玩家能根據實際狀況做出決策，是策略功能從「設定」到「互動」的關鍵延伸，但需先有賽前規劃（P1）才能有意義。

**Independent Test**：在比賽進行中，可驗證抬頭顯示器（HUD）是否持續顯示目前使用的輪胎種類、已行駛圈數與下次預計進站圈次。

**Acceptance Scenarios**:

1. **Given** 玩家正在比賽中，**When** 畫面常駐顯示策略資訊，**Then** HUD 顯示目前輪胎種類、本組輪胎已使用圈數及下次預計進站圈次（若有）。
2. **Given** 玩家已使用超過預設進站圈次而未進站，**When** 超過設定圈次時，**Then** 進站提示以警示樣式顯示，提醒玩家當前策略已偏離計畫。
3. **Given** 玩家在比賽中進站並完成換胎，**When** 離開維修站後，**Then** HUD 更新為新輪胎種類、已使用圈數歸零，並顯示下一段策略的進站圈次（若尚有安排）。

---

### User Story 3 - 比賽後檢視策略執行回顧 (Priority: P3)

玩家完成比賽後，可以在成績畫面中查看本場策略執行摘要，包含實際進站圈次與原計畫的比較，了解策略決策對最終成績的影響。

**Why this priority**：策略回顧讓玩家能從每場比賽中學習並優化未來策略，提升遊戲的深度與重玩動機，但屬於提升體驗的功能，而非核心可玩性所必需。

**Independent Test**：完成一場有進站操作的比賽後，可驗證成績畫面是否顯示策略執行摘要，包含計畫進站圈次、實際進站圈次及各段輪胎使用圈數。

**Acceptance Scenarios**:

1. **Given** 玩家剛完成比賽，**When** 成績畫面顯示，**Then** 頁面包含「策略回顧」區塊，列出每次進站的計畫圈次與實際圈次對照。
2. **Given** 玩家完成比賽後查看策略回顧，**When** 本場有實際執行進站，**Then** 顯示每段輪胎種類與實際使用圈數，並標示是否符合賽前計畫。
3. **Given** 玩家完成比賽但未按計畫進站，**When** 查看策略回顧，**Then** 系統標示哪些進站計畫未執行，並顯示實際所使用的輪胎種類。

---

### Edge Cases

- 玩家設定的進站圈次超過比賽總圈數時，系統應提示錯誤並拒絕儲存該計畫。
- 玩家未設定任何策略直接開始比賽時，系統應允許以「無策略」模式進行，不顯示任何進站提示。
- 玩家設定多次進站但在比賽中提早退出時，策略回顧應僅顯示已執行部分，未執行部分標示「未完成」。
- 玩家在同一圈次設定兩次進站計畫時，系統應提示衝突並要求修正後才可儲存。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系統 MUST 提供獨立的策略規劃畫面，讓玩家在比賽開始前設定進站計畫。
- **FR-002**：系統 MUST 支援玩家在策略規劃畫面中選擇每次進站的目標圈次（範圍為第 1 圈至最終圈前一圈）。
- **FR-003**：系統 MUST 提供至少三種輪胎選項（軟胎、中性胎、硬胎）供玩家在每次進站時選擇換裝種類。
- **FR-004**：系統 MUST 允許玩家在策略規劃畫面中新增、修改及刪除進站計畫，並在儲存後顯示完整策略摘要。
- **FR-005**：系統 MUST 在比賽進行中，當到達設定的進站圈次前一圈時，在畫面顯示「準備進站」提示。
- **FR-006**：系統 MUST 在比賽 HUD 中持續顯示目前輪胎種類、本組輪胎已使用圈數及下次預計進站圈次。
- **FR-007**：系統 MUST 在玩家實際進站完成換胎後，自動更新 HUD 的輪胎資訊並切換至下一段策略。
- **FR-008**：系統 MUST 在比賽結束後的成績畫面提供策略執行回顧，對比計畫進站圈次與實際進站圈次。
- **FR-009**：系統 MUST 驗證策略設定的合法性（進站圈次不超過總圈數、同一圈次無重複進站），並在無效時提示錯誤。
- **FR-010**：玩家 MUST 能夠選擇不設定任何策略直接開始比賽，此時系統以「無策略」模式進行，不顯示任何進站提示。

### Key Entities

- **策略計畫（Race Strategy）**：代表玩家為一場比賽設定的完整進站安排，包含多個進站計畫項目，屬於比賽開始前的設定資料。
- **進站計畫項目（Pit Stop Entry）**：策略計畫中的單一進站設定，包含目標圈次與換裝的輪胎種類；一個策略計畫可包含零至多個進站計畫項目。
- **輪胎（Tyre）**：代表賽車目前使用的輪胎種類（軟胎/中性胎/硬胎）及其已使用圈數，影響 HUD 顯示與策略回顧資料。
- **策略執行紀錄（Strategy Execution Log）**：比賽結束後生成，記錄每個進站計畫項目的計畫圈次與玩家實際進站圈次，用於回顧顯示。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：玩家能在 2 分鐘內完成賽前策略規劃（包含設定進站圈次與輪胎選擇）並開始比賽。
- **SC-002**：比賽中策略提示（進站提醒與 HUD 資訊）在 90% 的測試場景中正確顯示且無遺漏。
- **SC-003**：90% 的玩家首次使用策略規劃畫面時，無需說明文件即可成功設定並儲存至少一筆進站計畫。
- **SC-004**：比賽結束後策略回顧頁面能正確呈現全場每次進站的計畫與實際對比，準確率達 100%。

## Assumptions

- 本規格假設玩家已能完成基本賽車遊戲流程（對應 Feature 001 的核心比賽功能），策略規劃功能建立在可運作的比賽系統之上。
- 初始版本支援最多 3 次進站計畫，足以涵蓋標準 F1 策略範疇，未來可依需求擴充。
- 輪胎種類初版提供軟胎、中性胎、硬胎三種，暫不包含雨胎（待後續天氣系統功能加入時再擴充）。
- 策略資料僅存於本場遊戲的執行階段記憶體中，比賽結束後不持久化儲存（除非玩家成績存檔功能明確要求）。
