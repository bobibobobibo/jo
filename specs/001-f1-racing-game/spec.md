# Feature Specification: F1 賽車遊戲

**Feature Branch**: `001-f1-racing-game`  
**Created**: 2026-03-13  
**Status**: Draft  
**Input**: 做一個F1遊戲  
**Language**: 繁體中文（敘述文字強制；程式碼與專有名詞可保留原文）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 駕駛 F1 賽車完成比賽 (Priority: P1)

玩家在瀏覽器中開啟遊戲，選擇開始比賽後，透過鍵盤控制一輛 F1 賽車在賽道上行駛，完成指定圈數即為完成比賽，並顯示最終成績。

**Why this priority**: 這是遊戲的核心體驗——沒有可玩的賽車主迴圈，其他所有功能都毫無意義。能夠獨立交付一個可遊玩的最小版本（MVP）。

**Independent Test**: 可透過開啟遊戲主頁、按下「開始比賽」並操控賽車跑完至少一圈來完整驗證；若能成功計算圈數並顯示完賽畫面即通過測試。

**Acceptance Scenarios**:

1. **Given** 玩家已開啟遊戲主畫面，**When** 玩家按下「開始比賽」，**Then** 賽道與賽車出現，計時器開始倒數，玩家可立即使用鍵盤控制賽車移動。
2. **Given** 玩家正在比賽中，**When** 玩家使用方向鍵（或 WASD）操控賽車，**Then** 賽車依照輸入在賽道上加速、減速、轉向，且不會穿越賽道邊界。
3. **Given** 玩家正在比賽中，**When** 賽車越過終點線完成所有圈數，**Then** 遊戲顯示「完賽」畫面，並呈現總用時。

---

### User Story 2 - 查看成績與最佳圈速 (Priority: P2)

玩家完成比賽後，可以看到本場比賽的詳細成績（包含每圈圈速與總用時），並能查看歷史最佳圈速紀錄。

**Why this priority**: 成績回饋讓玩家有動力反覆挑戰，是提升遊戲重玩價值的關鍵功能，但在核心賽車體驗可玩之後才有意義。

**Independent Test**: 完成一場比賽後，可驗證成績畫面是否顯示每圈圈速、總用時，以及最佳圈速是否正確保存並在下次比賽後比較更新。

**Acceptance Scenarios**:

1. **Given** 玩家剛完成比賽，**When** 完賽畫面顯示，**Then** 畫面列出每一圈的完成時間與本場總用時。
2. **Given** 玩家曾多次完成比賽，**When** 查看成績畫面，**Then** 顯示歷史最佳圈速，並標示本場是否創下新紀錄。
3. **Given** 玩家首次遊玩，**When** 完成第一場比賽，**Then** 自動將本場最佳圈速存為歷史紀錄基準。

---

### User Story 3 - 選擇賽車與賽道 (Priority: P3)

玩家在開始比賽前，可以從多個選項中選擇不同外觀的賽車及不同佈局的賽道，增加遊戲多樣性。

**Why this priority**: 選車與選賽道是豐富遊戲內容的延伸功能，提升可玩性，但不影響核心遊戲機制的可運作性。

**Independent Test**: 可在主選單中分別選取不同賽車與賽道組合，進入比賽後驗證所選賽車圖示及賽道佈局是否正確對應顯示。

**Acceptance Scenarios**:

1. **Given** 玩家在遊戲主選單，**When** 玩家瀏覽賽車選擇畫面，**Then** 顯示至少 3 款不同外觀的 F1 賽車供選擇，點選後可確認選擇。
2. **Given** 玩家已選好賽車，**When** 玩家瀏覽賽道選擇畫面，**Then** 顯示至少 2 條不同佈局的賽道（例如：高速賽道、技術性彎道賽道）。
3. **Given** 玩家選好賽車與賽道後按下「開始比賽」，**When** 遊戲載入，**Then** 賽道佈局與所選一致，賽車外觀與所選一致。

---

### Edge Cases

- 玩家未完成比賽即關閉頁面或重新整理時，進度不保留，返回主選單。
- 賽車碰撞賽道邊界時，應減速或反彈，而非穿越邊界或卡住。
- 玩家連續快速按下多個方向鍵時，遊戲應平滑回應，不發生控制失靈或抖動。
- 在比賽途中若瀏覽器分頁失去焦點（玩家切換分頁），遊戲應自動暫停，重新聚焦後可繼續。
- 最佳圈速紀錄儲存失敗（例如：瀏覽器封鎖本地儲存）時，遊戲應仍可正常遊玩，僅靜默跳過成績保存。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須在瀏覽器中顯示一個可互動的 F1 賽道場景，包含賽道邊界與賽車。
- **FR-002**: 系統必須允許玩家透過鍵盤方向鍵（或 WASD）控制賽車的加速、減速與轉向。
- **FR-003**: 系統必須偵測賽車的碰撞邊界，防止賽車穿越賽道外側區域。
- **FR-004**: 系統必須追蹤並顯示目前圈數與已完成的圈速計時。
- **FR-005**: 系統必須在玩家完成所有圈數後顯示完賽畫面，包含每圈圈速與總用時。
- **FR-006**: 系統必須將玩家的歷史最佳圈速保存在本地，供下次遊玩時比較。
- **FR-007**: 系統必須在比賽開始前提供主選單，讓玩家選擇開始比賽。
- **FR-008**: 系統必須提供至少 3 款可選擇的 F1 賽車外觀。
- **FR-009**: 系統必須提供至少 2 條可選擇的賽道佈局。
- **FR-010**: 系統必須在瀏覽器分頁失去焦點時自動暫停遊戲，並在重新聚焦後恢復。
- **FR-011**: 系統必須可部署為靜態網頁，無需後端伺服器。

### Key Entities

- **賽車（Car）**: 代表玩家操控的 F1 賽車，具有位置、速度、方向、外觀樣式等屬性。
- **賽道（Track）**: 代表比賽場地，具有賽道佈局（邊界、直道、彎道）、圈數設定、起跑線位置等屬性。
- **比賽（Race）**: 代表一場正在進行或已完成的比賽，關聯一輛賽車與一條賽道，記錄各圈圈速、總用時、完賽狀態。
- **圈速紀錄（Lap Record）**: 代表玩家在特定賽道上的歷史最佳單圈時間，與賽道關聯，持久保存於本地。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家從開啟遊戲主頁到進入比賽的整體流程，可在 30 秒內完成。
- **SC-002**: 遊戲畫面更新頻率達到每秒 30 格以上，確保視覺流暢不卡頓。
- **SC-003**: 鍵盤輸入回應延遲在玩家可感知的範圍內（操控感覺即時，無明顯延遲）。
- **SC-004**: 玩家在首次接觸遊戲時，無需任何說明即可在 2 分鐘內理解操控方式並完成第一圈。
- **SC-005**: 90% 的完賽流程可正確顯示每圈圈速與總用時，無資料遺失或顯示錯誤。
- **SC-006**: 最佳圈速紀錄在重新整理頁面後依然保留，跨次遊玩數據不流失（正常瀏覽器環境下）。

## Assumptions

- 遊戲目標平台為現代桌面瀏覽器（以鍵盤為主要輸入裝置），不特別針對行動裝置觸控操作。
- 遊戲為單人體驗，不需多人連線或排行榜功能。
- 賽車物理模擬採用簡化模型（非真實 F1 物理引擎），重點在遊戲樂趣而非模擬真實性。
- 遊戲中不包含車輛損壞、天氣變化、換胎策略等進階 F1 要素，以維持範圍精簡。
- 歷史成績以本地儲存機制保存，無需使用者帳號或雲端同步。
- 遊戲圈數預設為 3 圈，賽道可在選單中切換但不提供自訂賽道功能。
